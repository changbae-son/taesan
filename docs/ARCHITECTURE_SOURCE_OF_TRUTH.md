# 근본 재설계 — 3대 정본(Source of Truth) 고정으로 "수정 없는 관리"

작성: 2026-06-16 / 사용자 확정 방향

## 0. 목표
단편적 수정의 악순환("고치면 다른 게 깨진다")을 끝내고, **키움 재수집·reconcile을
다시 돌려도 값이 안 바뀌는** 구조를 만든다. → 앞으로 수정 없이 관리.

## 1. 재발의 진짜 원인 (한 줄)
> 같은 값을 **여러 곳에서 만들고(다중 작성자)**, **매번 다시 만들고(재계산)**,
> **추정으로 만든다(자동 분류)**.

증거(이번 세션 사례):
- 평단 수정 → positions 평단 불일치 (다중 작성자)
- 매도 dedup 수정 → kt00007 중복 (수집 소스 불일치)
- 슬롯 자동분류가 다른 가격 매도 합산 (추정 강제) — 앱클론 +5%에 6/15·6/16 합쳐 18주
- 룰B 설정해도 buyPlans 안 바뀜 (재계산 트리거 누락) — 네이블

## 2. 해결 원칙 (한 줄)
> 값을 **한 곳에서만 만들고(단일 작성자)**, **한 번 확정하면 안 만들고(불변)**,
> 사실은 **키움/사용자 확정으로만 정한다(추정 금지)**.

## 3. 3대 정본 (각 계층의 유일 소스)

| 계층 | 정본(유일 소스) | 규칙 |
|---|---|---|
| ① 체결 사실 | 키움 **주문번호(ord_no)** = 주문체결상세 **kt00007** | 가격·수량·신용 = 키움 그대로. 한 번 저장 = **불변**(재수집해도 안 덮음) |
| ② 잔고·평단 | 키움 잔고 API(kt00005 buy_uv) | 시스템 재계산 **금지** (이미 단일진실 재설계로 적용됨) |
| ③ 분류(슬롯) | **사용자 확정** | 자동(수익률 밴드)은 빈 칸 **제안만**. 충돌 시 미분류. **확정 후 잠금**(reconcile 불변) |

- **파생(잔고표시·슬롯집계)은 저장하지 않음** — 항상 위 3개에서 계산만. (저장하면 작성자가 또 늘어남)

## 4. 왜 재발이 멈추는가
- **체결**: ord_no가 키움 고유 → 같은 가격·수량도 충돌 0, 단가 정확.
  누락(현대약품 168)·중복(앱클론18·시지메드텍198)·단가오류(161214 7850→7800) 원천 차단. 재수집해도 불변.
- **분류**: 사용자 확정 슬롯을 reconcile이 절대 안 바꿈. 자동 합산 모순 소멸. 애매하면 미분류.
- **재계산**: 체결·분류·룰 변경 시 자동 트리거 → "설정했는데 안 바뀜" 소멸.

## 5. 이행 순서 (단계마다 전 종목 연관성 검증 게이트)
1. **체결 정본화** — kt00007(ord_no) 정본 + 기존 fallback 1회 마이그레이션(**분류 승계** 필수).
   → 누락·중복·단가 원천 차단. ※ 마이그레이션 없이 단순 적용하면 기존 fallback과 중복(이번에 확인).
2. **분류 잠금** — 사용자 확정 슬롯 보존 + 같은 라운드+슬롯 충돌(다른 날/가격/ord_no) 시 미분류.
   ※ 부분체결(같은 날·가격·주문)은 합산 유지(1회 매도).
3. **자동 재계산 트리거** — 룰B 설정·저점 확정·체결 변경 시 reconcile 자동(네이블 케이스).
4. **상설 검증** — 매 변경마다 "키움 정본 = 시스템" 전 종목 진단 게이트.
